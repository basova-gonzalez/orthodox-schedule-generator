# Генератор расписания богослужений

Небольшой локальный инструмент для программиста: из одного файла с данными за месяц он создаёт самостоятельный HTML-блок. Блок содержит свои стили и подходит для поля «свой HTML» на разных сайтах. Перевода нет: для каждого языка нужен отдельный входной файл и отдельный блок.

![Пример двух языковых блоков](examples/preview.png)

## Запуск

Нужен Python 3.10+; сторонние пакеты не нужны.

```bash
python3 src/generate.py examples/month_ru.json output/month_ru.html
python3 src/generate.py examples/month_en.json output/month_en.html
python3 -m unittest discover -s tests -v
```

Месяц и год читаются из JSON. Имя файла или папки на них не влияет. Результат — фрагмент HTML со встроенным `<style>`, без `html`, `head` и `body`. `output/` содержит готовые блоки для примера. Чтобы посмотреть их вместе, откройте `examples/preview.html`.

## Формат входа

UTF-8 JSON, один месяц и один язык на файл:

```json
{
  "year": 2026,
  "month": 4,
  "language": "ru",
  "days": [
    {
      "date": "2026-04-07",
      "description": ["Описание дня", "Вторая строка"],
      "services": [
        {"time": "10:00", "title": "Название службы", "hours": "Храм открыт с 09:30", "priest": "Священник: пример"}
      ]
    }
  ]
}
```

`date` — гражданская дата `YYYY-MM-DD` внутри указанного месяца. Дни могут идти в любом порядке; генератор отсортирует их и отклонит повторы. `description` — список обычных текстовых строк. `services` — список служб по порядку; у каждой обязательны четыре поля. `time` строго `HH:MM`, остальные поля — строки, в том числе пустые. Пустые `hours` и `priest` не выводятся. Все строки экранируются как текст HTML; вставить разметку через данные нельзя. Поля называются одинаково на любом языке.

Каждый выведенный день имеет `data-schedule-date="YYYY-MM-DD"`. Воскресенья, Пасха и двунадесятые праздники выделяются красным по расчёту, независимо от написания описания. Используется юлианская пасхалия; неподвижные праздники переводятся из старого стиля в гражданские даты. Поддержаны годы 1900–2099.

## Настройки

Всё в `settings.json`: `colors.text`, `colors.accent`, `colors.red` — цвета HEX; `font_family` — список локальных или системных шрифтов; `max_width_px` — ширина блока; `additional_highlight_dates` — список дополнительных дат `YYYY-MM-DD` (изначально пуст). Для каждого кода языка в `languages` задайте `title`, двенадцать `months` с января по декабрь и семь `weekdays` с понедельника по воскресенье. Число языков не ограничено. Для другого файла настроек передайте `--settings путь/к/settings.json`.

Стили ограничены классом `.orthodox-schedule`. Внешние шрифты, скрипты и сетевые ресурсы не подключаются. На узком экране две колонки становятся одной.

## Вставка на сайт

Скопируйте **всё содержимое** нужного выходного HTML-файла в блок пользовательского HTML. В Тильде это блок T123; в WordPress — блок «Произвольный HTML». В другом конструкторе найдите аналогичный блок «Свой HTML». Для двух языковых страниц вставьте соответствующий отдельный файл на каждую страницу. Некоторые платформы фильтруют тег `<style>`; тогда потребуется разрешённый ими способ добавления CSS.

## Если у вас иначе

Шаблон рассчитан на явные даты, описания и службы. Если структура вашего расписания другая, можно дополнить код вручную или попросить нейросеть. Например:

> У меня есть этот локальный генератор. Добавь необязательное поле `note` к каждой службе. Сохрани экранирование HTML, атрибут `data-schedule-date`, расчёт праздников и самостоятельный блок со стилями. Обнови пример, README и тесты. Не добавляй разбор текста по ключевым словам.
